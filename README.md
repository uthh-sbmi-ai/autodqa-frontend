# AutoDQA Frontend

Static web console for AutoDQA (autonomous data quality assessment of the
clinical data warehouse). Served via the institution's Cloudflare (behind
Cloudflare Access); previously hosted on AWS CloudFront + S3.

## Contents

- `index.html` — the single-page console UI
- `app.js` — sign-in (Cognito) + streaming invoke of the Bedrock AgentCore
  Runtime; renders each reason → act → observe step live
- `config.js` — generated deployment config (Cognito region/client id, runtime
  ARN, model id). Not secret — these values are shipped to every browser — but
  environment-specific.
- `uth_logo.svg` — the UTHealth Houston logo signature, required by the
  institutional web standards. Referenced by `index.html`, so it has to ship
  with it.

The footer carries a revision date required by the web standards. It is stamped
by `frontend/stamp_revision.py` in the upstream repo, run immediately before the
files are copied here — so the date reflects the deploy. Do not hand-edit it, and
keep the `<time id="revdate">` element intact; the script matches on that id and
exits non-zero if it cannot find exactly one.

## How it works

The browser authenticates against Amazon Cognito, then invokes the AgentCore
Runtime directly with the Cognito JWT. There is no backend in this repo — it is
purely static files; all state and secrets live in the AWS stack.

## Source of truth

These files are maintained in the main AutoDQA repository
(`ai-enabled-data-curation`, GitLab) under `frontend/`, where `config.js` is
generated by `frontend/make_config.py`. Update there and copy here to deploy —
do not edit here directly.
